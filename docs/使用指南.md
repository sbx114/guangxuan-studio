# 光宣工作台使用指南

## 打开与选择项目

双击桌面的 **光宣工作台** 快捷方式，或完整程序目录中的 **启动光宣工作台.cmd**。兼容入口使用已有Node.js 24和Edge独立窗口。关闭窗口会保留后台；需要关闭服务或加载更新时，先保存工作，再使用程序目录中的停止或重启入口。

首页三维方块对应实际保存的项目，没有项目时显示空档案。选中一个项目并进入详情，可查看名称、简介、类型、时长或内容统计。修改名称与简介后点击保存，再确认进入编辑：视频项目打开原生剪辑，文案项目进入写作。改名不移动原生工程目录，迟到的旧自动保存也不会覆盖新名称。

从编辑器返回时会先提交待写入内容，再保留当前详情。再次进入同一项目复用已加载的编辑器；隐藏工作区会暂停播放与动画，已提交的导出任务可在后台继续。后端会话变化时缓存会重新准备。

## 模型连接

在模型连接中填写服务商提供的API基础地址、模型ID和API Key。选择实际支持的Chat Completions或Responses；JSON模式仅在接口支持时开启。列表不可读取时，可以手动填写模型ID。

保存后测试连接。测试会发出真实短请求，可能使用服务额度；通过后再用短素材验证完整任务。工作台密钥默认只保留当前会话，Electron版可选系统加密保存。原生编辑器的可选服务单独配置，不能把工作台连接成功当作所有原生服务均已配置。

不要把密钥放入项目正文、标题、截图或导出文件。应用不会自动把密钥重新发送到其它本地端口。

## 文案写作

1. **素材与需求**：粘贴正文或导入TXT、Markdown、DOCX，填写来源链接、受众、语气和篇幅。链接用于留档，不代表应用已自动读取整个网页。
2. **事实确认**：提炼后核对人物、日期、地点、数字及“暂定”等限定，再确认事实。引句匹配只证明文字出现在素材中。
3. **内容创作**：生成推文、海报文案、视频分镜和社群文案，手动编辑或使用AI改写。
4. **核查与导出**：检查具体问题和依据，导出Word、Markdown、海报PNG、文案JSON及来源、提示词和修改记录。

修改素材后要重新检查旧事实和草稿。分镜里的画面是制作建议，时长属于脚本设计，不是已生成镜头或语音识别结果。制作记录的模型等待时间也不等于完整任务耗时。

文案和分镜可以转入视频工作区。已有预置示例明确标为“预置演示，非本次实时AI生成”，不作为实时调用或试用成绩。

## 原生视频工作区

### 进入工程与手动编辑

在项目详情确认进入视频编辑后，打开对应的原生电影工程。使用原生素材区、预览、多轨时间线、属性面板和画布进行剪切、顺序调整、音量、字幕及其它编辑；保存和导出以该电影工程为准。

旧视频项目首次进入时，会将受控素材、片段出入点、字幕和配乐转成原生工程，同时保留旧JSON与来源快照。后续原生编辑不会反向覆盖旧时间线快照，因此不要用旧JSON判断最新剪辑状态。

新复制的素材保留安全化原名并加短ID，字幕页带序号；已有工程不批量重命名，重新打开不会改写原电影。

工作台辅助导入会将文件流式保存到本机再检查，单文件最多2GB；原生素材导入使用原生工作流。导入到本地并不等于上传中转站。存在外部链接的素材，备份或AI处理前应先收集到工程中。

### AI粗剪与版本保护

打开辅助面板，读取当前工程的实际媒体和主画面轨，根据素材名称、类型、尺寸、时长与来源脚本生成方案。它不识别画面中的人物、动作或精彩瞬间。

检查方案后再应用。方案绑定读取时的原生版本；如果生成期间继续改了电影，应用旧方案会被拒绝，应刷新上下文并重新检查，不会自动覆盖新编辑。

主画面轨含有HTML页面、外部链接、禁用片段或无法读取的媒体时，粗剪可能无法完整表示这些内容，此时禁止应用。将相关内容整理为独立原生轨或修复素材后再试。其它独立原生轨道保留，不因主轨粗剪被删除。

默认粗剪只处理主画面轨；只有明确提供时才更新桥接生成的字幕、配乐轨。写作脚本可独立保存，不自动覆盖原生字幕。文案估时需对照播放调整，不能当作语音识别的时间轴。

### Remotion动画

用文字编排可编辑JSON，支持标题、步骤、数据条、引用和收尾五类模板；支持16:9、9:16、1:1，paper/dark主题及30fps。每场3—12秒，最多8场、总长90秒。

校验后本机真实渲染为MP4，可追加到当前原生工程。数据条的数字需要实际依据，人物引语需要原始出处。模型只编排约定结构，不执行任意生成代码。

没有密钥时可以使用预置方案真实渲染；展示时说明方案是预置、视频由本机渲染，不说成实时AI生成。

### 导出和完整备份

使用原生编辑器的导出功能生成成片，完成后检查画面、音量、字幕和时长。工作台仍保留原有媒体导出能力；新视频工程的最终编辑以原生film为准。

**视频项目备份以完整原生工程目录或原生项目导出为准，JSON不能代替。** 应保留 `film.html`、媒体、页面及需要恢复的原生设置、画布和历史。外部链接素材先收集进工程，避免换电脑后缺少文件。

如果要一并恢复光宣档案中的名称、简介、文案和来源，还要保存对应的Root JSON。文案项目的JSON备份可以恢复写作内容；不要把它与完整视频工程备份混为一谈。

## 数据保存位置

兼容版数据根目录是 `%LOCALAPPDATA%\GuangxuanStudio`，与安装目录 `%LOCALAPPDATA%\Programs\GuangxuanStudio` 分开：

| 相对数据根目录的路径 | 用途 |
| --- | --- |
| `projects/<项目ID>.json` | 项目资料、来源、文案与旧剪辑数据 |
| `openfilm/projects/<项目ID>/film.html` | 当前原生电影 |
| `openfilm/projects/<项目ID>/assets/`、`pages/`、`.film/` | 原生媒体、页面、画布、设置及历史 |
| `openfilm/projects/<项目ID>/legacy-project.json` | 首次迁移快照 |
| `openfilm/state/` | 本应用独立的原生状态与配置 |
| `openfilm/exports/` | 原生成片 |

迁移不改写原JSON；详情中的改名会更新其元数据。最近修改时间取Root项目资料、原生film和主画布已知修改时间的较晚值，不需要重写原JSON。独立于本应用的 `~/.openfilm` 不会被读取或修改。

工作台中转密钥默认仅会话；原生服务配置按其设置保存在本应用原生状态目录。主动AI操作会发送相应资料或元数据到用户选择的服务，本地保存并不意味着AI全程离线。

## 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 详情仍无项目 | 新建或打开实际保存的项目；空档案不会显示虚构方块 |
| 计划版本已变化 | 刷新原生上下文，再重新检查或生成方案 |
| 主轨暂不可粗剪 | 检查HTML、禁用、外链或不可读片段，先整理或修复 |
| 401、403、404、429 | 分别检查密钥权限、接口和模型ID、额度或限流 |
| 本地工作服务失联 | 重新使用桌面入口打开健康服务，不把密钥改发其它端口 |
| 原生编辑器尚未构建 | 源码版需生成Studio UI dist；发行版请使用完整程序目录 |
| 缺少FFmpeg或浏览器 | 保留发行资源，确认本机Edge/Chrome；源码版配置FFmpeg路径 |
| 字幕不准 | 对照实际播放调整；估时不是ASR |
| JSON恢复后找不到最新视频 | 恢复完整原生工程目录与媒体，JSON只保留关联资料和旧剪辑 |

许可证、商标和素材说明随源代码与发行文件保留，见第三方许可文档，不作为创作界面的额外署名入口。
